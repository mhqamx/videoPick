## 1. 产品概述（Goals & Background）

**一句话定位**
VideoPick 是一款跨平台移动端工具，用户粘贴主流社交 / 短视频平台的分享链接即可一键下载**无水印**的视频或图文到本地相册。

**项目背景**
主流社交与短视频平台（抖音、TikTok、Instagram、X、B 站、快手、小红书）出于内容保护与流量管控考虑，普遍未提供原生的"保存到本地"入口；即便允许下载，文件中也会嵌入平台水印。市面上的第三方下载工具大多存在以下问题：

- 仅支持单一平台，跨平台需要切换多个工具；
- 广告嵌入严重、付费墙频繁；
- 要求登录账号、强制上传到云端；
- 对图文类内容（小红书图集、Instagram Carousel 等）支持薄弱。

VideoPick 针对上述痛点，以"**粘贴即下、零账号、无水印、视频图文并重**"为产品理念，做一款主流平台一站式覆盖的下载工具。

**现阶段目标**
本 PRD 不规划新增功能，而是把当前已交付的能力沉淀为正式文档：

1. 形成可对外说明的产品全貌；
2. 作为业务团队、客服、新成员的统一参考；
3. 为未来的演进（新平台扩展、UX 升级）保留接口和上下文。

## 2. 目标用户与使用场景

**用户画像**
普通 C 端移动端用户。典型特征：

- 重度使用 1 ~ 3 个主流内容平台；
- 看到喜欢的视频或图文，希望保存到自己手机相册留念；
- 非批量搬运、非商业用途；
- 对"账号、登录、云盘"等概念敏感，更倾向纯本地工具。

**核心场景 ①｜视频保存**
用户在抖音 / B 站 / TikTok 等平台浏览时看到喜欢的视频 → 点击"分享 → 复制链接" → 切到 VideoPick → 粘贴 → 等待几秒 → 视频自动保存到相册。

**核心场景 ②｜图文保存**
用户在小红书 / Instagram / X 上看到摄影、穿搭、表情包等图集内容 → 复制链接 → 粘贴到 VideoPick → 一次性下载全部图片到相册，无需逐张长按保存。

视频与图文场景**同等重要**，PRD 中两者并列为核心能力。

## 3. 价值主张与差异化

| 卖点 | 说明 |
|---|---|
| **全平台覆盖** | 一个 App 覆盖 7 个主流平台，国内外不分主次 |
| **真·无水印** | 通过协议层处理（如抖音 `/playwm/` → `/play/`、TikTok 绕过 embed token 限制），保证下载到的素材干净 |
| **三端对等** | iOS / Android / Flutter 三个客户端在功能边界、平台支持、媒体类型上完全一致 |
| **零配置启动** | 多数平台无需登录或 Cookie，粘贴即下；只有需要登录态的平台（Instagram、X）才要求用户配置 |
| **隐私友好** | 无账号体系、无埋点上报、无云端存储，所有数据本地直存（详见 NFR2） |
| **无商业化干扰** | 无广告、无内购、无开屏，纯工具向产品 |

## 4. 功能需求（Functional Requirements）

### 4.1 链接解析（FR-P）

| 编号 | 需求 |
|---|---|
| **FR-P1** | 支持从用户粘贴的任意文本中自动提取平台 URL，包括短链形态（如 `v.douyin.com/xxx`、`vt.tiktok.com/xxx`、`xhslink.com` 等）。 |
| **FR-P2** | 客户端优先尝试本地解析的平台：抖音、小红书、快手、Instagram、X。本地解析失败时自动回退到 Backend。 |
| **FR-P3** | TikTok、B 站直接走 Backend 解析（这两类平台前端结构复杂或反爬严格，本地解析不稳定）。 |
| **FR-P4** | 解析结果统一返回数据结构，包含：媒体类型（`video` / `images`）、标题、作者、媒体 URL 列表。 |
| **FR-P5** | 解析过程对用户透明，进度状态可见；解析失败给出可读的错误说明而非技术堆栈。 |

### 4.2 媒体下载（FR-D）

| 编号 | 需求 |
|---|---|
| **FR-D1** | 视频下载：单文件直存到系统相册（iOS）或相册 / 下载目录（Android、Flutter）。 |
| **FR-D2** | 图文下载：多张图片逐张下载，全部完成后批量入相册。 |
| **FR-D3** | 大文件下载在不稳定网络下支持断点续传与自动重试。 |
| **FR-D4** | 所有下载经 Backend 代理（`/download?source=…` 端点）以避免移动端被 CDN 直接封锁；图片同样走代理。 |
| **FR-D5** | 下载过程显示进度反馈；失败给出明确错误说明。 |

### 4.3 Cookie 配置（FR-C）

| 编号 | 需求 |
|---|---|
| **FR-C1** | 对需要登录态的平台（Instagram、X）提供独立的 Cookie 设置页面。 |
| **FR-C2** | 用户填入的 Cookie 在本地持久化（iOS UserDefaults / Android SharedPreferences / Flutter shared_preferences），不上传到任何服务端。 |
| **FR-C3** | 解析请求自动携带对应平台 Cookie；用户首次访问需要 Cookie 的平台时给出引导。 |
| **FR-C4** | Cookie 设置页提供清晰的填写说明（哪些字段必填，如何获取）。 |

### 4.4 本地保存（FR-S）

| 编号 | 需求 |
|---|---|
| **FR-S1** | iOS 通过 PhotoKit 保存到系统「相册」。 |
| **FR-S2** | Android 通过 MediaStore 保存到「相册 / 下载」目录。 |
| **FR-S3** | Flutter 通过 `photo_manager` 走对应平台原生相册接口。 |
| **FR-S4** | 首次保存时按系统规范申请相册权限；权限被拒后给出引导提示。 |

### 4.5 输入辅助（FR-I · 含规划项）

| 编号 | 需求 | 状态 |
|---|---|:---:|
| **FR-I1** | App 每次进入前台（含冷启动）自动读取剪贴板内容；若内容相较"上次读取值"发生变化且疑似 URL，向用户给出提示并自动填入输入框。仅在 iOS 端先实现，Android / Flutter 后续跟进。 | 🚧 Planned |

## 5. 非功能需求（Non-Functional Requirements）

| 编号 | 类别 | 需求 |
|---|---|---|
| **NFR1** | 性能 | 单次解析（含 Backend 回退）目标 P95 < 5 秒。下载吞吐受网络限制，但需在网络可用时稳定不中断。 |
| **NFR2** | 隐私 | 无用户账号、无埋点上报、无云端存储。所有用户数据（Cookie、已下载文件）仅存本地。Backend 仅做无状态的解析与代理，不留存请求内容。 |
| **NFR3** | 跨端一致性 | iOS / Android / Flutter 三端在"支持平台、媒体类型、Cookie 能力"三个维度上完全对等。 |
| **NFR4** | 网络容错 | 不稳定网络下支持自动重试；iOS 大文件支持断点续传；Backend 下载走流式转发以减少内存占用。 |
| **NFR5** | 可扩展性 | Backend 采用 Extractor 插件架构，新增平台只需新建 Extractor 类并在注册表中登记，不改动核心流程。 |
| **NFR6** | 高可用 | 客户端内置多个 Backend URL，按优先级回退（局域网 IP 优先，公网备用），降低单点故障概率。 |

## 7. UX 原则

- **极简首屏**：主界面只有一个粘贴输入框和一个下载按钮，无任何多余元素。
- **零配置启动**：用户首次打开应用即可使用主流平台；只有进入 Instagram / X 场景才会引导到 Cookie 配置。
- **过程可见**：解析中、下载中、保存中均有明确的进度反馈；失败给出可读的错误说明，避免暴露技术细节（如堆栈、HTTP code）。
- **视觉无干扰**：无广告位、无开屏广告、无引导弹窗、无升级提示轰炸。
- **平台无差别体验**：用户不需要预先告知"我要下抖音还是 TikTok"，App 根据 URL 自动识别。

## 8. Non-Goals 与边界

为避免功能蔓延，以下能力在**当前阶段明确不做**：

| 不做的事 | 原因 |
|---|---|
| ❌ 批量下载 / 自动化抓取 | 产品定位为"个人收藏单条保存"，批量场景属于爬虫工具范畴，与产品价值观相悖。 |
| ❌ 用户账号 / 云同步 / 在线收藏夹 | 与"隐私友好、纯本地"的产品理念冲突；引入账号会显著抬升复杂度与合规风险。 |
| ❌ 视频剪辑 / 滤镜 / 二次创作 | 偏离工具定位，且该领域已有大量成熟产品。 |
| ❌ 任何形式的商业化 | 当前阶段保持纯工具属性；付费会员 / 广告 / 内购均不引入。 |

**未划定边界（保留探索空间）**：
- "内容发现 / 历史记录"等轻量功能未被明确排除，作为未来开放探索方向（详见第 10 节）。

## 9. 已知限制与依赖

| 类别 | 风险 / 限制 | 缓解措施 |
|---|---|---|
| **平台前端变化** | 各平台 HTML / API 结构会随版本变化，导致解析失败。 | 采用多级回退（如抖音 `_ROUTER_DATA` → `_SSR_HYDRATED_DATA` → `RENDER_DATA` → 正则）；Backend 集中维护 Extractor 便于快速修复。 |
| **Instagram / X 登录门槛** | 这两个平台必须用户提供 Cookie 才能解析，存在使用门槛。 | Cookie 设置页提供清晰的获取教程；本地持久化降低重复填写成本。 |
| **Backend 可用性** | Backend 是部分平台的必经路径，存在单点故障风险。 | 客户端内置多个 Backend URL 优先级回退；Backend 采用 stateless 设计便于横向扩展。 |
| **CDN 风控** | TikTok、Instagram 等平台 CDN 反爬策略可能临时阻断下载。 | Backend 代理下载架构允许在服务端集中升级绕过策略，无需客户端发版。 |
| **平台合规** | 第三方下载工具与平台条款之间存在灰色地带。 | 产品定位为个人本地保存、不做转发分发；不做账号体系以降低合规面。 |

## 10. 后续演进方向（开放，非承诺）

以下为可能的演进方向，不构成当前 PRD 的需求承诺：

- **新增平台**：YouTube Shorts、Threads、微博、Pinterest 等可纳入 Extractor 体系。

- **国际化**：界面多语言支持（当前以中文为主）。

#### Story 7.1 详情

**User Story**
> 作为一个普通用户，我希望每次打开 App 或从后台切回 App 时，App 能自动识别我刚才复制的链接并填到输入框里，这样我不用每次都手动点"粘贴"。

**触发时机**
- iOS App 冷启动后进入前台；
- 已在内存中的 App 从后台回到前台（SwiftUI `scenePhase` 由 `.background` / `.inactive` 切换到 `.active`）。

**验收标准（Acceptance Criteria）**

| AC | 标准 |
|---|---|
| **AC1** | App 每次进入 `.active` 状态时，调用一次 `UIPasteboard.general.string` 读取剪贴板内容。 |
| **AC2** | 维护一个内存中的"上次已处理剪贴板内容"缓存（不需要跨启动持久化）；仅当本次读取值非空且与缓存不同才进入提示流程。 |
| **AC3** | 进入提示流程时，向用户展示轻量提示（toast / banner / inline 提示均可），文案示意：「已识别到剪贴板内容，已自动填入输入框」。 |
| **AC4** | 将剪贴板内容自动填入主输入框（用户可继续编辑或直接点击下载）。 |
| **AC5** | 接受 iOS 系统在读取剪贴板时显示的"已粘贴自 XX"系统横幅，作为隐私透明度的代价；不做规避。 |
| **AC6** | 当前阶段仅 iOS 端实现；Android / Flutter 不在本 Story 范围内，作为后续 Story 跟进。 |

**实现要点（非约束性提示，供开发参考）**
- 在 SwiftUI App / Scene 层订阅 `scenePhase`；
- ViewModel 持有"上次剪贴板"字段（普通 `String?` 即可，无需 `UserDefaults`）；
- 提示形态采用与现有 UI 一致的轻量 toast，避免引入新依赖。

**Out of Scope（明确不做）**
- 不做 URL 合法性校验（任何非空文本只要与上次不同就走流程，让用户决定）；
- 不做自动解析 / 自动下载（仅填入输入框）；
- 不做 Android / Flutter 实现（独立 Story 后续承接）。

## 附录 · 词汇表

| 术语 | 含义 |
|---|---|
| **Extractor** | Backend 中每个平台对应的解析器类（继承自 `BaseExtractor`），负责该平台的 URL 提取与内容解析。 |
| **Backend 代理下载** | 客户端不直接从平台 CDN 下载，而是通过 Backend 的 `/download?source=...` 接口由 Backend 中转，避免移动端被 CDN 封锁。 |
| **本地解析** | 客户端直接抓取平台移动端页面 HTML 并解析其中的 JSON / 正则，无需 Backend 参与。 |
| **无水印** | 通过协议层手段获取不含平台 logo / 用户名水印的原始媒体文件。 |
