# Story 8.1 Architecture — Android + Flutter Parity for Clipboard Auto-Read

> 产出角色：Architect Agent（Plan subagent_type） · 日期：2026-05-25
> 上游：Story 7.1（iOS 已实现） · 下游：SM Agent 切 Story 8.1.x

---

## 1. Decision Summary

For Android, observe foreground via `LifecycleEventObserver` on `LocalLifecycleOwner` inside the top Composable (`VideoPickApp`), keep the `lastClipboardContent` cache as a private field in `DownloadViewModel`, expose `clipboardHint: String?` on `UiState`, and render the 3-second hint as a custom inline Card inside `DownloadScreen` (NOT a Snackbar). For Flutter, attach `WidgetsBindingObserver` to `DownloadViewModel` itself (it already extends `ChangeNotifier`), keep `_lastClipboardContent` private, expose `clipboardHint`, and render the hint as a Provider-driven inline banner inside the existing `status_section.dart`. Both ports preserve iOS Story 7.1 semantics: read on every foreground transition, in-memory cache, fill input on mismatch, dismiss after 3s.

---

## 2. Decisions

### Decision A1 — Android lifecycle observation mechanism

| Option | Mechanism | Pros | Cons |
|---|---|---|---|
| **A (recommended)** | `LifecycleEventObserver` on `LocalLifecycleOwner.current` inside `VideoPickApp`, registered via `DisposableEffect(Unit)` | Compose-idiomatic; covers cold launch (`ON_START`/`ON_RESUME` fire) and resume; survives recomposition cleanly; ViewModel stays Android-framework-pure | Slight boilerplate vs. `Activity.onResume` |
| B | Override `MainActivity.onResume()` and call `viewModel.checkClipboardOnForeground()` | Simplest mental model | Couples Activity to ViewModel; awkward because ViewModel is currently obtained inside Compose (`viewModel()`); breaks "Compose owns state" pattern |
| C | `ProcessLifecycleOwner.get().lifecycle.addObserver(DefaultLifecycleObserver)` | Survives Activity recreation; fires once per process foreground | Does NOT re-fire on same-Activity background→foreground while process is alive; semantics mismatch with iOS `scenePhase` |

**Recommendation: A.** Use `ON_RESUME` (matches iOS `.active`). Anchor: `android/app/src/main/java/com/demo/videopick/MainActivity.kt::VideoPickApp`.

### Decision A2 — Cache placement (`lastClipboardContent`)

**Recommendation: A.** Private `var lastClipboardContent: String? = null` field in `DownloadViewModel`; new public `fun checkClipboardOnForeground()` using `getApplication<Application>().applicationContext`. NOT in `UiState` (avoid recomposition triggers). Anchor: `android/app/src/main/java/com/demo/videopick/viewmodel/DownloadViewModel.kt`.

### Decision A3 — Clipboard read API

**Recommendation:** `(context.getSystemService(Context.CLIPBOARD_SERVICE) as ClipboardManager).primaryClip?.getItemAt(0)?.coerceToText(context)?.toString()`. `coerceToText` safer than `.text` for URI/intent clips.

Pitfalls:
- Android 12+ shows a system toast "App pasted from clipboard" on every read — accepted (mirrors iOS AC5).
- `primaryClip` may be `null` on first launch — treat as no-op.
- Lifecycle callbacks run on Main; safe.

### Decision A4 — Hint UI mechanism

**Recommendation: A.** Custom inline `Card` in `DownloadScreen`, shown when `state.clipboardHint != null`, auto-dismissed via `viewModelScope.launch { delay(3000); … }` inside VM. Visually matches iOS `clipboardHintView()` (blue card in status section, inline, not overlay). Snackbar rejected to preserve cross-end visual parity.

### Decision F1 — Flutter lifecycle observation

**Recommendation: A.** `DownloadViewModel implements WidgetsBindingObserver`. Register in constructor via `WidgetsBinding.instance.addObserver(this)`; unregister in `dispose()`. Trigger on `AppLifecycleState.resumed`. VM owns the lifecycle hook (symmetric with iOS VM owning scenePhase-triggered callback).

### Decision F2 — Cache placement

**Recommendation: A.** Private `String? _lastClipboardContent` field on `DownloadViewModel`. No `notifyListeners()` when only cache mutates.

### Decision F3 — Flutter hint UI

**Recommendation: A.** Provider-driven inline blue card in `status_section.dart`, reusing existing `_StatusCard` visual idiom. Auto-dismiss `Timer(Duration(seconds: 3), …)` lives in VM. SnackBar via `ScaffoldMessenger` rejected (bottom overlay diverges from iOS inline placement).

### Android — `MainActivity.kt::VideoPickApp` addition

```kotlin
val lifecycleOwner = androidx.lifecycle.compose.LocalLifecycleOwner.current
DisposableEffect(lifecycleOwner) {
    val observer = LifecycleEventObserver { _, event ->
        if (event == Lifecycle.Event.ON_RESUME) viewModel.checkClipboardOnForeground()
    }
    lifecycleOwner.lifecycle.addObserver(observer)
    onDispose { lifecycleOwner.lifecycle.removeObserver(observer) }
}
```

## 4. Cross-Platform Consistency Constraints

以下语义在 Android / Flutter 必须与 iOS Story 7.1 完全一致：

1. **触发频率：** 每次前台切换都读取一次（冷启动 + 每次 background→foreground）。Android: `ON_RESUME`。Flutter: `AppLifecycleState.resumed`。
2. **缓存范围：** 仅内存。**禁止**持久化到 `SharedPreferences` / `shared_preferences` / disk。私有 VM 字段，进程终止即丢失。
3. **比较逻辑：** 读取值 (a) 非 null AND (b) 非空字符串 AND (c) `!= lastClipboardContent`。三条件全满足才进入填入流程。
4. **缓存更新时机：** 在成功填入后立即更新 `lastClipboardContent`，不受用户后续编辑影响。重复复制同样的字符串故意是 no-op。
5. **输入填入行为：** 替换（不是追加）`inputText`。用户后续可继续编辑。
6. **提示时长：** **恰好 3 秒**，由 VM 拥有的可取消 `Timer` / `Job` 自动消失。重新触发时**取消并重启**，不堆叠。
7. **提示视觉：** 状态区内联蓝色卡片，**不是** Snackbar / Toast / Overlay。图标 = clipboard-paste（`Icons.ContentPaste` / `Icons.content_paste`）。
8. **提示文案：** 三端**完全相同的中文字符串**：`已识别到剪贴板内容，已自动填入`（iOS 已锁定，SM 在 Story 中以常量形式约束）。
9. **不做 URL 校验：** 任何非空差异文本都触发填入。
10. **接受系统横幅：** Android 12+ 的 clipboard-access toast 和 iOS 的"已粘贴自"横幅都不规避（继承 iOS AC5）。
11. **Share-Intent 优先：** Android `MainActivity.handleShareIntent` 在 `onCreate` 中先于 `setContent` 执行，会在首次 `ON_RESUME` 之前填入 `inputText`。VM 必须能识别这种"输入已被 share 填入"的情况并 no-op（详见 SM 的 AC）。

## 5. Risks & Fallbacks

| 决策 | 风险 | 回退 |
|---|---|---|
| A1 `LocalLifecycleOwner` 导入位置 | Compose 不同版本下从 `androidx.compose.ui.platform` 迁移至 `androidx.lifecycle.compose`，import 错位会编译失败 | 若 `androidx.lifecycle:lifecycle-runtime-compose` 不在依赖中，回退到 `androidx.compose.ui.platform.LocalLifecycleOwner` |
| A3 `primaryClip` 在无焦点时为 null | `ON_RESUME` 时焦点已授予，正常情况下安全 | null 或 item count == 0 时静默 no-op |
| A4 用户在 3s 内切到后台 | hint 隐式存活 3s 然后再返回时仍可见 | 接受（iOS `Task.sleep(3s)` 也有相同行为） |
| F1 测试环境 `WidgetsBinding.instance` 未初始化 | VM 构造时抛错 | 测试用 `TestWidgetsFlutterBinding.ensureInitialized()` 包裹 |
| F3 未来 `status_section.dart` 重构 | hint 位置约定可能丢失 | 在代码注释和本 ADR 中固化位置契约 |
| 3s 内连续触发 | 计时器堆叠 | 两端都 cancel-and-restart 取消旧任务再建新任务（已写入 contract） |
